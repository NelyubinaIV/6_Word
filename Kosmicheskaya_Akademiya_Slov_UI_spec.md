# ТЗ на ученическую интернет-страницу
## «Космическая академия слов»

**Версия:** 1.0  
**Дата фиксации:** 13 августа 2026  
**Назначение:** единое техническое и дизайнерское ТЗ для создания красивого ученического кабинета и экранов выполнения заданий.  
**Референс:** приложенный интерфейс в космическом стиле с тёмно-синим фоном, фиолетово-синими карточками, яркими акцентами и игровым ощущением.  
**Важно:** блок **«Мини-игры» не нужен** и в интерфейс не добавляется.

---

# 1. Главная идея

Нужен не просто «дашборд с карточками», а полноценная ученическая веб-страница, которая ощущается как игровая образовательная платформа.

Визуально страница должна напоминать приложенный референс:

- глубокий тёмно-синий космический фон;
- звёзды, мягкие световые орбиты, небольшие космические декоративные элементы;
- карточки с мягким стеклянным/неоновым эффектом;
- крупные понятные цифры;
- аккуратная игровая типографика;
- яркие акценты: жёлтый, бирюзовый, синий, фиолетовый;
- ощущение «миссии», прогресса и движения вперёд;
- интерфейс современный, дорогой и чистый, без визуального перегруза.

При этом все цифры, статусы и действия должны опираться только на реально существующие данные backend/YDB. Не придумывать пользователю кристаллы, серии дней, награды или статистику, если их ещё нет в API.

# 3. Что нельзя придумывать в интерфейсе

## Не показывать сейчас как рабочие данные:

- кристаллы/монеты;
- мини-игры;
- календарь активности;
- недельную серию/streak;
- «слово дня»;
- рейтинг;
- место среди других учеников;
- XP, если это не возвращает сервер;
- количество достижений, если нет отдельного API;
- статистику класса;
- сообщения учителя;
- вымышленные задания/миссии.

Если позже появится backend для этих функций, их можно будет добавить отдельным этапом.

# 4. Что можно показывать прямо сейчас

`GET /dashboard` уже возвращает реальные данные:

```json
{
  "userId": "usr_test_student_001",
  "newCount": 0,
  "reviewDueCount": 0,
  "difficultCount": 0,
  "learnedCount": 10,
  "masteredCount": 0,
  "totalActiveWords": 10,
  "stars": 90,
  "nextReviewAt": "2026-08-14T17:51:20Z"
}
```

Поэтому в интерфейсе можно и нужно показывать:

- имя ученика;
- количество звёзд;
- количество новых слов;
- количество слов на повторение сегодня;
- количество сложных слов;
- общий прогресс;
- изучено слов;
- полностью освоено слов;
- ближайшую дату повторения;
- текущую учебную сессию;
- результаты завершённого занятия.

# 5. Структура страницы

## 5.1. Левая боковая панель

Стиль — как в референсе: тёмная вертикальная панель слева, крупные иконки + подписи.

### Обязательные пункты

```text
🚀 Космическая академия слов

🏠 Главная
📘 Новые слова
🔁 Повторение
🧩 Сложные слова
📊 Мой прогресс
📖 Словарь
⚙ Настройки
↪ Выйти
```

### Важное правило

Пункты меню должны соответствовать существующим возможностям.

На первом этапе:

- **Главная** — работает;
- **Новые слова** — работает;
- **Повторение** — работает;
- **Сложные слова** — работает;
- **Мой прогресс** — можно открыть как отдельный экран на основе `/dashboard`;
- **Словарь** — пока можно показывать как отдельный экран только если данные берутся из текущей учебной выборки; полноценный словарь позже;
- **Настройки** — минимально: профиль + выход, без сложной логики;
- **Выйти** — обязательно вызывает `/logout`.

Не добавлять пункт «Мини-игры».

  - кабинет;
  - настройки;
  - выйти.

# 9. Три основные карточки

Ниже главного блока — три яркие карточки в одну линию.

## Карточка 1 — Новые слова

Цвет: синий / электрик.

```text
🚀 Новые слова

{newCount}

Изучай новые слова, значение и правильное написание.

[Начать]
```

Если `newCount = 0`:

- кнопка disabled;
- карточка остаётся красивой;
- текст:
  ```text
  Новых слов сейчас нет
  ```

---

## Карточка 2 — Повторение

Цвет: бирюзовый / сине-зелёный.

```text
🔁 Повторение

{reviewDueCount}

Слова, срок повторения которых уже наступил.

[Повторить]
```

Если `reviewDueCount = 0`:

```text
Следующее: {nextReviewAt}
```

---

## Карточка 3 — Сложные слова

Цвет: розово-фиолетовый.

```text
🧩 Сложные слова

{difficultCount}

Отдельная тренировка слов, в которых было две ошибки.

[Отработать]
```

---

# 10. Блок «Общий прогресс»

Оформление: широкая карточка на всю доступную ширину.

Показывать:

```text
Общий прогресс

10 из 10
████████████████████ 100%

Изучено: 10
Полностью освоено: 0
```

Расчёт:

```text
studied = learnedCount + masteredCount
progressPercent = studied / totalActiveWords * 100
```

Не считать `difficult` и `learning` как полностью изученные.

---

# 11. Дополнительный блок вместо «Мини-игр»

На месте блока «Мини-игры» из референса ничего игрового не добавлять.

Лучше использовать пространство для одного из полезных блоков:

## Вариант A — «Ближайшее повторение»

```text
🕒 Следующее повторение
14 августа, 20:51

Слово появится автоматически, когда наступит время.
```

## Вариант B — «Последняя миссия»

Если позже добавится API истории:

```text
Последнее занятие
10 слов
8 с первой попытки
2 после повторения
⭐ +90
```

До появления API истории использовать **вариант A**.

## 12.1. Карточка нового слова

Дизайн должен быть заметно богаче текущего технического экрана.

### Слева

Большое слово:

```text
аккура́тный
```

Трудные буквы подсвечиваются жёлтым.

Ниже:

```text
Тот, кто действует чисто, точно и бережно.
```

### Справа

Крупное изображение слова.

Если изображения нет:

- не показывать серую техническую заглушку;
- использовать красивую декоративную космическую иллюстрацию/плашку;
- не писать «изображение добавим позже» в production.

### Кнопки

```text
🔊 Послушать
Проверить себя
```

Если аудио отсутствует — кнопку аудио скрывать.

# 13. Экран проверки написания

Верхняя подпись:

```text
ПРОВЕРЯЕМ НАПИСАНИЕ
```

Центральное предложение:

```text
У ученика был [      ]ратный почерк.
```

Поле ввода должно быть крупным и встроенным прямо в предложение.

Кнопки:

```text
← К карточке
Проверить
```

После проверки:

### Правильно с первой попытки

```text
Верно! ⭐ +10
```

Сервер:

```text
action = learned_first_try
```

### Первая ошибка

```text
Пока не получилось.
Слово вернётся через 3 других слова.
```

Сервер:

```text
action = repeat_later
```

### Правильно со второй попытки

```text
Верно! ⭐ +5
```

Сервер:

```text
action = learned_after_retry
```

### Вторая ошибка

```text
Слово отправлено в «Сложные».
Мы вернёмся к нему отдельно.
```

Сервер:

```text
action = mark_difficult
```

# 14. Повторение

Запуск:

```http
POST /start-session
```

```json
{
  "mode": "review"
}
```

## Главное отличие

При интервальном повторении **не показывать карточку с правильным словом заранее**.

Ученик сразу видит:

```text
ИНТЕРВАЛЬНОЕ ПОВТОРЕНИЕ
```

и упражнение.

---

## Правильный ответ

Пример:

```text
Верно!
Следующее повторение через 3 дня.
```

---

## Ошибка

```text
Есть ошибка.
Слово вернётся через 3 других слова.
```

Если со второй попытки верно:

```text
Верно!
Следующее повторение через 1 день.
```

Если снова ошибка:

```text
Слово отправлено в «Сложные».
```

# 15. Интервальная схема

Система уже работает по схеме:

```text
изучение
↓

↓
3 дня
↓
7 дней
↓
14 дней
↓
30 дней
↓

```

На экране не обязательно показывать всю техническую схему.

Можно визуально показывать путь как «звёздную траекторию»:

```text
●━━●━━●━━●━━●━━★
```

Но только декоративно, без вымышленных данных.

# 16. Сложные слова

Запуск:

```http
POST /start-difficult-session
```

## Сценарий

1. Показать карточку.
2. Дать ученику снова увидеть правильное написание.
3. Показать значение.
4. Затем дать упражнение.

### Если ученик ответил правильно

```text
Отлично!
Слово возвращено в обычный цикл.
Повторение через 1 день.
```

Backend:

```text
action = difficult_recovered
```

### Если снова ошибка

```text
Слово пока остаётся в разделе «Сложные».
Мы вернёмся к нему в следующей тренировке.
```

Backend:

```text
action = difficult_still_wrong
```

# 19. Logout

Кнопка:

```text
Выйти
```

обязана вызывать:

```http
POST /logout
Authorization: Bearer <token>
```

Только после ответа сервера:

- очистить токен;
- очистить данные пользователя;
- показать форму входа.

Даже если сервер временно недоступен, браузер можно очистить, но ошибку нужно писать в console.

# 20. Форма входа

Экран должен быть красивым и соответствовать общей стилистике.

## Левая часть

- название;
- робот/космический персонаж;
- небольшая фраза.

Пример:

```text
Космическая академия слов

Тренируй память.
Собирай звёзды.
Осваивай сложные слова.
```

## Правая часть

```text
Вход в академию

Логин
[                  ]

Пароль
[                  ]

[ Войти ]

Нет аккаунта?
Регистрация будет добавлена позже.
```

# 26. Анимации

Допустимы:

- мягкий hover карточки;
- лёгкое свечение CTA;
- плавное заполнение progress bar;
- появление результата;
- небольшая анимация звезды при +10/+5;
- лёгкий floating у робота/планеты;
- переходы экранов 150–300 ms.

Не использовать:

- мигающие элементы;
- резкие вращения;
- тяжёлые постоянные анимации;
- бесконечные конфетти.

---

# 27. Адаптация для мобильного

На ширине менее 900 px:

- sidebar превращается в верхнее/выезжающее меню;
- карточки идут в одну колонку;
- учебное предложение переносится аккуратно;
- поле пропуска остаётся частью предложения;
- кнопки занимают удобную ширину;
- заголовки уменьшаются.

Минимальная рабочая ширина:

```text
360 px
```

# 28. Доступность

Обязательно:

- достаточный цветовой контраст;
- кнопки минимум 44 px по высоте;
- видимый `focus`;

- `aria-label` на полях пропусков;

# 29. Работа с API

# 31. Критическое требование безопасности

Frontend отправляет:

```json

  "wordId": 1,
```

Frontend **не должен получать `correct_letters`**.

Backend сам сравнивает ответ с YDB.

# 37. Что считать готовым MVP интерфейса

Интерфейс считается готовым, если ученик может:

9. завершить сессию;
10. вернуться в кабинет;
11. увидеть обновлённые данные;
12. открыть повторение;
13. пройти интервальную проверку;
14. открыть сложные слова;
15. успешно отработать их;
16. увидеть ближайшее повторение;
17. выйти;

# 38. Проверка на ошибки

Обязательно проверить:

### Login

- правильный пароль;
- неправильный пароль;
- пустой логин;
- истёкший token;
- revoked token.

### Dashboard

- новые слова = 0;
- review = 0;
- difficult = 0;
- каждый из счётчиков > 0;
- `nextReviewAt = null`;
- `nextReviewAt` заполнен.

### Learning

- правильный ответ;
- первая ошибка;
- повтор через три слова;
- вторая правильная;
- две ошибки.

### Review

- правильный ответ;
- ошибка;
- правильный со второй попытки;
- две ошибки.

### Difficult

- правильная отработка;
- повторная ошибка.

### Logout

```text
POST /logout → 200
старый token → /dashboard 401
```

# 40. Итоговая формулировка задачи для разработчика / Copilot

> Создай полноценный frontend ученического кабинета «Космическая академия слов» на чистом HTML/CSS/JavaScript. Визуальный стиль должен повторять эстетику приложенного референса: премиальный тёмный космический UI, глубокие сине-фиолетовые панели, яркие игровые акценты, звёзды, орбиты, мягкое свечение, крупные карточки, качественная типографика. Не добавляй блок «Мини-игры».
>
> Интерфейс обязан работать только с реальными данными существующего Yandex Cloud API. Не придумывай кристаллы, серии дней, награды, календарь или статистику, которых нет в API.
>
> Используй маршруты:
>
> ```text
> POST /login
> POST /logout
> GET /dashboard
> POST /start-session
> POST /start-difficult-session
> GET /words
> POST /check
> POST /finish-session
> ```
>
> Реализуй единый SPA-подобный интерфейс без перезагрузки страницы:
>
> ```text
> login
> → dashboard
> → new/review/difficult
> → task
> → result
> → finish-session
> → dashboard refresh
> → logout
> ```
>
> Все защищённые запросы выполняй с Bearer token.
>
> Правильные ответы никогда не храни во frontend и не получай из API: браузер отправляет только `wordId` и ответ ученика, а проверку выполняет backend.
>
> Основной dashboard должен содержать:
>
> - имя ученика;
> - звёзды;
> - новые слова;
> - повторение сегодня;
> - сложные слова;
> - общий прогресс;
> - ближайшее повторение.
>
> Экран новых слов: сначала карточка с полным словом, ударением, значением, изображением и аудио (если есть), затем упражнение с пропуском.
>
> Интервальное повторение начинается сразу с упражнения без показа правильного слова.
>
> Сложные слова сначала снова показывают карточку, затем упражнение.
>
> После каждого занятия обязательно вызывать `/finish-session` и затем заново загружать `/dashboard`.
>
> Сделай интерфейс адаптивным для desktop/tablet/mobile. Все локальные пути должны быть относительными и совместимыми с GitVerse Pages.
>
> Не меняй backend API и не переименовывай поля ответа сервера без отдельного согласования.
